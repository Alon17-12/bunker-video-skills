# קובץ האפיון של בונקר אקספרס — סכמה v1

הלקוח ממלא את הטופס בבונקר; השליחה יוצרת **קובץ HTML אחד** בתיקיית המסירה (`אפיון — <תוכנית> — <תאריך>.html`).
אנשים קוראים אותו בדפדפן; הסוכן קורא את הבלוק המוטמע:

```html
<script type="application/json" id="bunker-express-spec">{ … }</script>
```

`$PY -m bsession spec "<session>" "<html>"` → `אפיון.json` (המבנה שכל הסקריפטים קוראים) + עותק `אפיון.html` בסשן.
דוגמה מלאה: `tests/fixtures/express-spec-v1.html` (האפיון של אורח R #62).

| שדה | סוג | מה הוא משנה בעריכה |
|---|---|---|
| `v` | 1 | גרסת הסכמה. אחרת — הסוכן עוצר ומבקש קובץ חדש |
| `show`, `client` | טקסט | שם התוכנית בקבצים, בכרטיסים, במסירה |
| `booking_date` | YYYY-MM-DD | תאריך הסשן |
| `speakers[]` | `{name, role}` | שמות על המסך + התפקיד בשורה השנייה. הסדר: הראשון = מיקרופון/מצלמה 1, זהב; השאר לבן — עד אישור «מי זה מי» |
| `look.mode` | `brand` / `site` / `logo` | `brand`/`site`: פונט וצבעים מדף הנחיתה; `logo`: הלוגו שהועלה |
| `look.site_url` | URL | דף הנחיתה לשאיבת המותג |
| `look.logo_url` | URL או null | הלוגו שהלקוח העלה (יורד ל-`לוגו.png`). **קישור וגם לוגו → הלוגו שהועלה, אף פעם לא לוגו מהאתר** (`landing_page.logo_from_site = false`) |
| `reels.count` | מספר | כמה רילס (10 בשירות) |
| `reels.music` | בוליאני | מוזיקה מתחת לרילס |
| `reels.tone` | `warm` / `calm` / `energetic` / `light` | סגנון המוזיקה (חם וקצבי / רגוע / אנרגטי / חם וקליל) |
| `reels.logo` | בוליאני | לוגו מתחת לכתוביות |
| `reels.reference_url` | URL | ירד מהטופס ב-18.10 (תמיד ריק). בגרסה הבאה: רילס לדוגמה מהעמוד שלנו |
| `episode.names_on_screen` | בוליאני | כרטיסי שם בכניסה של כל דובר |
| `episode.logo` | בוליאני | לוגו בפינה הימנית העליונה |

| `terms[]` | טקסט | מילים שחשוב לכתוב נכון בכתוביות |
| `notes` | טקסט | הערות חופשיות |
| `template` | בוליאני | פודקאסט קבוע — הטופס הבא נפתח מלא |

**כללים לרנדרר בבונקר:**
- כל `<` בתוך ה-JSON נכתב כ-`\u003c` (JSON תקין) — זה מכסה גם `</script>` וגם `<!--` בטקסט של לקוח, שהיו שוברים את הדף
  בדפדפן. הקורא כאן מקבל גם `<\/` (קובץ הדוגמה).
- `id="bunker-express-spec"` במירכאות כפולות, בדיוק כך.
- שינוי שובר בסכמה = `v` חדש, והקורא כאן מתעדכן באותו סבב.
- כמה קבצי אפיון לאותו סשן (הלקוח שלח שוב) — הסוכן לוקח את האחרון (חותמת הזמן בשם / `submitted_at`).
